Implemented app and backend fixes

- Parent GCash/Maya checkout sends the authenticated session, prevents repeated taps, supports reopening checkout, and verifies provider payment before opening its receipt. Unpaid checkouts never credit a wallet.
- Bank top-ups require confirmation and return a transaction/receipt ID through the transactional writer.
- Parent home, parent history, and admin home expose receipt actions with icons. Cashier home has the same receipt icon.
- Parent profile no longer offers PIN changes.
- Admin account edits persist names, locations, usernames, and parent-child links. Parent rows are unique by parent ID; Edit / Link another student accepts comma-separated student IDs and retains those listed. A student linked to another parent is rejected.
- Parent, cashier, and canteen account deletion runs transactionally after the app's confirmation. Historical receipts are retained. Canteen products referenced by receipts are detached and deactivated.
- Account cleanup triggers compare IDs consistently, fixing the database collation error that prevented deletion.
- Canteen wrong-PIN responses stay on PIN entry, preserving the order; locked accounts remain blocked.
- The scanned-student bill selection has a back button. A newly added custom payment opens its payment flow.
- Cashier payments/custom payments verify the student's PIN and debit the student, crediting the signed-in cashier. Top-ups verify the cashier's PIN and debit that cashier, crediting the student.
- Cashier dashboards show the stored balance; top-ups display as debits rather than receipts of money.

Installation

The changed PHP files are synchronized between `updated/edupay` and `rawr/edupay`. On this PC they were installed in `C:\xampp\htdocs\edupay`. Run `php account_cleanup_migration.php` from the deployed backend when installing elsewhere. It is safe to rerun. The migration changes cleanup triggers, not user rows or balances.

Original deployed files and triggers were backed up to `backend-backup-20260909-141517` in the workspace root. The updated debug APK was built for `http://192.168.254.184/edupay` and installed on the connected TECNO BG7 without clearing app data.
